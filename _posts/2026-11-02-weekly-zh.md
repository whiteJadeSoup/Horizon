# Horizon 创业周报 · 2026-11-02

> 最近采集存在不可用信源，详情见网页。

## TLDR

### 核心看点

- Mistral Large 4开放权重，K2 Horizon披露训练全链路材料；性能仍需复现，商业许可须单独核对。
- 陪伴产品出现两种具体玩法：多角色群聊与合照，以及把虚拟宠物养成、语音记录和日记结合。
- 实用工具聚焦创作与开发流程：从视频制作游戏原型、管理长篇设定、串联漫剧制作，以及编码前的独立审查。

### 趋势分析

- 推断：开放模型的竞争正从权重扩展到数据、检查点和运行日志；材料完整性与可复现性可能成为选型维度。
- 推断：陪伴产品正尝试把单聊扩展为群体互动与日常养成；现有材料尚不能证明这些玩法改善留存。

## 技术前沿发展

### Mistral Large 4开放权重，模型服务另议许可

- **发生了什么**：第三方帖子转述发布文章、模型卡与许可：模型支持百万token上下文、多模态输入和文本输出，并提供面向Blackwell的NVFP4检查点。所列基准均为Mistral披露，未经独立审计。
- **为什么重要**：厂商报告Terminal-Bench 4.0达到41%，较预览版提升13个百分点。转述许可条款涉及经营模型服务的主体及其关联方，并区分内部使用、终端产品嵌入与模型服务，不能仅凭“开放权重”判断适用性。
- **可借鉴之处（判断）**：先用自有任务比较成功率、总成本与部署要求。涉及托管推理、后训练服务或模型服务关联业务时，应核对原始许可，而非仅依赖帖子摘要。

**证据口径**：第三方报道

> Every benchmark figure below is Mistral's own and unaudited.

[原文](https://x.com/botnewsnetwork/status/2115860036417470603) · X/@botnewsnetwork

### K2 Horizon称已交付训练全链路开放材料

- **发生了什么**：发布方自述材料包括六个模型的380个检查点、13万亿预训练token及58次训练运行日志。RL360披露8192个并发沙箱、约130万次rollout等运行规模；这些是发布方口径。
- **为什么重要**：MoVA将MoE稀疏机制用于多头注意力的value向量，发布方称兼容高效注意力算法且不增加KV缓存成本。本周事件是材料交付声明，不应把此前预告写成本周首次提出。
- **可借鉴之处（判断）**：训练团队可先检查数据许可、仓库完整性和检查点可用性，再尝试利用日志定位训练故障或复现后训练路线。

**证据口径**：作者自述

> K2 Horizon 360 is way more: 8 artifact categories and 30+ repositories across every stage of LLM training.

[原文](https://x.com/IFM_AI/status/2115851165724500284) · X/@IFM_AI

### Liquid发布LFM3，采用三混合架构

- **发生了什么**：输入引用的原始公告列出文本、视觉、音频、全模态及决策模型共六个实例。第三方转述称1.7B文本模型开放权重，4位量化约需1GB内存，采用LFM Open License v1.0。
- **为什么重要**：可关注的变化是架构组合、模型体量及模态覆盖，而非厂商榜单排名。约1GB是转述中的量化内存口径，不能推导为256K上下文下的整机运行内存。
- **可借鉴之处（判断）**：端侧团队应按目标设备测试延迟、峰值内存和任务质量。单GPU微调及跨处理器优化均为发布方主张，需在实际配置验证。

**证据口径**：第三方报道

> tri-hybrid architecture (convolution, sliding-window and global attention), 256K-token context, about 1 GB of memory at 4-bit.

[原文](https://x.com/LLMreference/status/2115860082663784527) · X/@LLMreference

### Girl Chat 2.0加入三角色群聊与合照 · AI陪伴·软件

- **发生了什么**：此次变化以2.0版本说明为准，还包括首页、聊天和资料页改版，用户自我介绍入口，以及更快生成并在聊天中显示照片。长期记忆、语音等产品简介内容不计为本周新增。

**证据口径**：官方披露

### 据报Meta在菲律宾推出虚拟宠物Waddle World · AI陪伴·软件

- **发生了什么**：据帖子，用户可以孵化、喂养宠物并玩短小游戏，不设置每日连续打卡或计分要求。宠物能把用户分享的经历整理为带涂鸦的日记，并可通过每周邮件汇总所了解的内容。
- **为什么重要**：该产品把陪伴嵌入照料与生活记录，区别于纯对话界面。当前证据是第三方发布帖，并非官方公告或独立实测；帖子称尚未宣布更广泛上线安排。
- **可借鉴之处（判断）**：创业者可借鉴“轻养成加记录”的循环，但需验证用户是否愿意持续分享，以及宠物反馈能否形成不同于普通日记工具的价值。

**证据口径**：第三方报道

- **商业化状态**：目前免费且免注册；未披露收费模式、广告或实际收入，商业化尚未得到验证。

## AI效率提升

### Video2Game把概念视频变成网页游戏原型

- **发生了什么**：报道转述作者已制作31款网页小游戏，fal调用总成本约202美元，Claude费用另算。流程还包括模拟操作、录制试玩画面、与原视频比较并修改；材料未明确这些作品的制作日期。
- **为什么重要**：价值在于把视觉概念转换为可操作的验证对象。平均约6.5美元仅覆盖作者披露的fal费用，不能当作每款游戏的完整开发成本；作品仍被描述为原型。
- **可借鉴之处（判断）**：先选范围小、交互明确的玩法试跑，同时记录模型与资产费用。验收应覆盖可玩性、控制反馈和实际画面，而不只比较截图。

**实践步骤**

1. 用MiniMax H3 Max生成一段10—15秒、玩法明确的游戏概念视频。
2. 将视频交给Claude，分析角色、场景、镜头与操作方式。
3. 通过项目流程调用fal生成资产，并用Three.js构建浏览器原型。
4. 录制实际试玩，与参考视频对比后修改，单独核算Claude及fal费用。

**证据口径**：第三方报道

> 根据作者公布的数据，31 款游戏的 fal API 调用总成本约 202 美元，平均每款约 6.5 美元，Claude 的费用另算。

### InkOS用设定持久化管理长篇创作

- **发生了什么**：输入称项目使用TypeScript与AGPL-3.0协议，提供Web工作台、TUI及CLI，接入多种LLM后端，还支持续写已有作品、风格迁移与EPUB导出。资料未证明这些功能均为本周新增。
- **为什么重要**：持久化设定和审计流程提供了管理长篇一致性的手段，但没有独立证据证明能消除剧情矛盾。更适合把它当作可回滚、可审核的创作工作台。
- **可借鉴之处（判断）**：先以少量章节验证人物、时间线和世界规则是否被正确引用，再扩大生成规模；已有作品续写尤其需要人工审核设定变化。

**实践步骤**

1. 选择Web工作台、TUI或CLI入口，接入所需LLM后端。
2. 建立世界观、人物设定和章节规划，先生成少量章节。
3. 运行审计与修订流程，人工核对人物、时间线及情节承接。
4. 不满意时回滚版本；审批后继续创作或导出EPUB。

**证据口径**：第三方报道

> ・多 Agent 流水线：规划→撰写→草稿→审计→修订，持久化世界观、人物设定，保障长篇剧情连贯性，支持版本回滚

[原文](https://x.com/ChinaAIDaily/status/2114726078862512348) · X/@ChinaAIDaily

### ArcReel串联剧本、分镜与剪映草稿

- **发生了什么**：据介绍，小说、剧本或商品素材可进入制作流程，角色、场景和道具参考图能在后续分镜复用。各阶段可人工调整或重新生成，生成后可进入剪映继续编辑；原文未明确首次发布日期。
- **为什么重要**：它整合的是制作流程，而不是证明生成模型已有新的底层能力。参考图复用提供了一致性管理手段，但输入没有提供稳定性实测或完整制作成本。
- **可借鉴之处（判断）**：先用一个短场景打通全链路，检查资产复用、分镜衔接和草稿可编辑性，再决定是否迁移现有项目。

**实践步骤**

1. 输入一段小说、剧本或商品素材，生成项目规划。
2. 生成人物、场景与道具参考图，人工确认后供分镜复用。
3. 组织分镜图、视频片段和旁白，逐阶段审核并重生成不合格部分。
4. 查看生成费用与用量，导出剪映草稿后调整字幕、配音和节奏。

**证据口径**：第三方报道

> 生成后还能导出剪映草稿，继续调整字幕、配音、节奏和转场。

### EGM让独立视角先审设计，再写代码

- **发生了什么**：输入称项目支持Claude Code、Codex和Antigravity，覆盖头脑风暴、规格撰写与多轮审查，最终由用户确认后进入开发。原文未提供项目首次发布或本次更新日期。
- **为什么重要**：关键不是简单增加Agent数量，而是隔离上下文：审查者只读方案和引用资料，可能更容易暴露未写明的前提。输入没有提供缺陷减少或效率提升的量化结果。
- **可借鉴之处（判断）**：适合需求含糊或存在历史包袱的改动。可先用一次小型设计评审验证它能否提出实质问题，再决定是否纳入团队流程。

**实践步骤**

1. 让保有项目背景、需求和历史决策的Agent起草设计方案。
2. 将方案及引用资料交给一个不读取此前聊天的独立审查Agent。
3. 要求审查者列出隐含假设、需求缺口和实现风险，并据此修订。
4. 完成必要的多轮审查，由人工确认后再进入编码。

**证据口径**：第三方报道

> 🐟 金鱼：不看此前聊天，只读方案及引用资料，找出隐含假设、需求漏洞和实现风险。
